outputs: One reviewed change with its reason and the feedback it rests on.
topics: [upkeep]

## Steps

1. Work on a branch, never on the default branch. Merging is publishing: every installed copy is a link to this folder.
2. Keep each change to one purpose: one lesson, one fix or one topic.
3. Write the reason in the change: what changed, why, and the ids of the feedback it rests on.
4. Run `brain index`, then `brain check`, and fix every block finding.
5. Wait for the decider for: agent.md, a rule or procedure moving to active, any retirement or deletion, and every draft from the dream. Never merge it yourself.
6. A rule or procedure goes active only when the decider approves. Then run `brain set-status <ref> active`.
7. When a process changes, search every rule, procedure, routine and agent.md for its terms, and update them all in one change.
8. If the description or the index changed, start a fresh session and ask one question that only the brain answers. The answer must cite a rule or procedure by its title.
